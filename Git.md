# Git — конспект

## 1. Git и GitHub

- **Git** — распределённая система контроля версий, которая позволяет отслеживать изменения в файлах и возвращаться к предыдущим состояниям проекта.
- **GitHub** — веб-платформа для размещения Git-репозиториев, совместной разработки и управления проектами.

## 2. Настройка Git

### Установка имени и электронной почты

```
git config --global user.name "Your Name"
git config --global user.email "your@email.com"
```

Параметр `--global` задаёт настройки для всех репозиториев текущего пользователя, если их не переопределить на уровне отдельного репозитория.

### Проверка настроек

```
git config --list
```

Выводит список действующих настроек Git.

## 3. Создание репозитория

```
git init
```

Инициализирует Git-репозиторий в текущей папке, создавая служебную структуру `.git`.

## 4. Три области Git

### 4.1. Working directory — рабочая директория

Рабочая копия проекта, в которой создаются и изменяются файлы.

Подготовить конкретный файл к коммиту:

```
git add main.py
```

Подготовить все новые и изменённые файлы в текущей директории и её поддиректориях, кроме исключённых:

```
git add .
```

### 4.2. Staging area — индекс, область подготовки

Содержит изменения, которые будут включены в следующий коммит.

Посмотреть текущее состояние файлов:

```
git status
```

После `git add` изменения попадают в индекс. Если изменить файл ещё раз, новые изменения могут остаться неподготовленными.

### 4.3. Repository — репозиторий

Содержит сохранённую историю проекта и объекты Git.

Создать коммит:

```
git commit -m "Add new feature"
```

Коммит фиксирует подготовленные изменения в истории репозитория.

Объекты Git хранятся в служебной директории `.git/objects` в формате loose-объектов или упакованных объектов.

## 5. Статусы файлов

| Статус | Значение |
|---|---|
| `Untracked` | Git ещё не отслеживает файл |
| `Staged` | Изменения подготовлены к коммиту |
| `Unmodified` | Отслеживаемый файл не изменён относительно последнего коммита |
| `Modified` | Отслеживаемый файл изменён, но изменения не подготовлены |

**Важно:** один файл может одновременно иметь подготовленные изменения и новые неподготовленные изменения.

## 6. Типы объектов Git

- **Blob** — хранит содержимое файла.
- **Tree** — описывает структуру каталога: имена файлов и подкаталогов со ссылками на соответствующие объекты.
- **Commit** — фиксирует состояние проекта и содержит ссылку на дерево.
- **Tag** — объект аннотированного тега, содержащий ссылку на другой объект, имя тега, сведения о создателе, дату и сообщение. Лёгкий тег (lightweight tag) — это ссылка, а не отдельный объект `tag`.

## 7. Идентификаторы объектов и SHA-1

В традиционном формате объектов Git идентификатор обычно вычисляется с помощью SHA-1.

Основные свойства SHA-1:

1. Принимает входные данные переменной длины.
2. Вычисляет хэш.
3. Выдаёт 160-битный результат, обычно записываемый как 40 шестнадцатеричных символов.

Пример условного идентификатора:

```text
a1b2c3d4e5f6...
```

Для loose-объекта Git первые два символа хэша используются как имя подкаталога, а оставшиеся символы — как имя файла

**Коллизия хэш-функции** — ситуация, когда разные входные данные дают одинаковый хэш.

## 8. Что содержит коммит

Коммит содержит:

- ссылку на объект `Tree`, описывающий состояние проекта;
- сведения об авторе;
- сведения о коммитере;
- сообщение коммита;
- ссылки на родительские коммиты, если они есть.

У каждого коммита есть собственный идентификатор.

## 9. Ветки в Git (Branches)

### Что такое ветка?

**Ветка (branch)** — это ссылка на определённый коммит. При создании новых коммитов ссылка ветки перемещается на новый коммит.

- Каждая ветка указывает на свой последний коммит.
- Ветки позволяют разрабатывать разные функции независимо друг от друга.
- По умолчанию Git обычно создаёт начальную ветку с именем `main` или `master` — это зависит от настроек Git.

### Основные команды для работы с ветками

| Команда | Назначение |
|---|---|
| `git branch` | Отображает список локальных веток |
| `git branch <branch-name>` | Создаёт новую ветку |
| `git checkout <branch-name>` | Переключается на существующую ветку |
| `git checkout -b <branch-name>` | Создаёт новую ветку и переключается на неё |
| `git branch -m <new-name>` | Переименовывает текущую ветку |
| `git branch -d <branch-name>` | Удаляет ветку, если Git считает её безопасной для удаления |
| `git branch -a` | Показывает локальные и известные Git ветки удалённого отслеживания |

**Важно:** нельзя удалить ветку, на которой ты сейчас находишься. Сначала нужно переключиться на другую ветку.


## 10. Слияние веток (Merge)

### Что такое слияние?

**Слияние (merge)** — объединение изменений из одной ветки в другую.

- **Receiving branch** — ветка, в которую вливаются изменения. Это текущая ветка.
- **Feature branch** — ветка, изменения из которой нужно объединить.

После слияния Git может создать **merge commit** — коммит слияния, у которого обычно два родительских коммита.

### Основные команды

```
git merge <feature-branch-name>
```

Объединяет изменения указанной ветки с текущей веткой.

```
git merge -m "Merge feature" <feature-branch-name>
```

Выполняет слияние и задаёт сообщение для создаваемого merge commit. Параметр `-m` указывается именно так, без пробела между дефисом и `m`.


В этом примере изменения из ветки `feature` объединяются с текущей веткой `main`.

## 11. Хостинг Git-репозиториев

Сервисы, например GitHub, позволяют хранить удалённые репозитории и обмениваться изменениями между компьютерами.

### Клонирование репозитория

```
git clone <url>
```

Создаёт локальную копию удалённого репозитория, включая историю коммитов и настройки удалённого репозитория.

### Удалённый репозиторий (Remote)

**Remote** — это имя и адрес удалённого репозитория, с которым связан локальный репозиторий.

`origin` — традиционное имя удалённого репозитория по умолчанию, создаваемое при обычном клонировании. Это соглашение об именовании, а не специальное зарезервированное слово.

### Основные команды для работы с удалёнными репозиториями

| Команда | Назначение |
|---|---|
| `git remote -v` | Показывает имена и URL удалённых репозиториев |
| `git clone <url>` | Клонирует удалённый репозиторий |
| `git branch -a` | Показывает локальные ветки и ветки удалённого отслеживания |
| `git pull` | Получает изменения из удалённого репозитория и интегрирует их в текущую ветку |
| `git push` | Отправляет локальные коммиты в удалённый репозиторий |

## 12. Связь локального репозитория с удалённым

### Добавление удалённого репозитория

```
git remote add origin <url>
```

Добавляет удалённый репозиторий с именем `origin` и указанным URL.

### Отправка ветки на сервер

```
git push -u origin <branch-name>
```

Отправляет локальную ветку в удалённый репозиторий и устанавливает связь отслеживания (upstream) для последующих операций `git push` и `git pull`.

Параметр `-u` — сокращение от `--set-upstream`.

## 13. Основные команды Git

### 13.1. Основные операции

| Команда | Назначение |
|---|---|
| `git init` | Создаёт Git-репозиторий в текущей папке |
| `git status` | Показывает состояние рабочего дерева и индекса |
| `git add <file>` | Подготавливает изменения файла к коммиту |
| `git add .` | Подготавливает новые и изменённые файлы в текущей директории и поддиректориях |
| `git commit -m "message"` | Создаёт коммит из подготовленных изменений |
| `git log` | Показывает историю коммитов |

### 13.2. Просмотр версий и переключение

| Команда | Назначение |
|---|---|
| `git checkout <commit-hash>` | Переключается на конкретный коммит; обычно приводит к состоянию `detached HEAD` |
| `git checkout <branch-name>` | Переключается на указанную ветку |
| `git switch <branch-name>` | Современная команда для переключения между ветками |
| `git switch --detach <commit-hash>` | Переключается на конкретный коммит без перехода на ветку |

### 13.3. Работа с ветками

| Команда | Назначение |
|---|---|
| `git branch` | Показывает список локальных веток |
| `git branch <branch-name>` | Создаёт новую ветку |
| `git checkout -b <branch-name>` | Создаёт ветку и переключается на неё |
| `git switch -c <branch-name>` | Создаёт ветку и переключается на неё |
| `git branch -m <new-name>` | Переименовывает текущую ветку |
| `git branch -d <branch-name>` | Удаляет ветку, если Git считает её безопасной для удаления |
| `git branch -a` | Показывает локальные ветки и ветки удалённого отслеживания |
| `git merge <branch-name>` | Объединяет указанную ветку с текущей |
| `git merge -m "message" <branch-name>` | Выполняет слияние с заданным сообщением для merge commit, если он создаётся |

### 13.4. Работа с удалёнными репозиториями

| Команда | Назначение |
|---|---|
| `git clone <url>` | Клонирует удалённый репозиторий |
| `git remote -v` | Показывает адреса удалённых репозиториев |
| `git remote add origin <url>` | Добавляет удалённый репозиторий с именем `origin` |
| `git pull` | Получает и интегрирует изменения из удалённого репозитория в текущую ветку |
| `git push` | Отправляет локальные коммиты в удалённый репозиторий |
| `git push -u origin <branch-name>` | Отправляет ветку и устанавливает связь отслеживания для последующих операций |

### 13.5. Настройки Git

| Команда | Назначение |
|---|---|
| `git config --global user.name "Your Name"` | Задаёт имя автора коммитов по умолчанию |
| `git config --global user.email "your@email.com"` | Задаёт email автора коммитов по умолчанию |
| `git config --list` | Показывает действующие настройки Git |
